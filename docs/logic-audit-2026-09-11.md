# Проверка логики ReZon — 11 сентября 2026

Проверены основные цепочки по исходному коду: загрузка и сохранение данных, миграции, импорт и аккаунты, каталог и поиск, альбомы/плейлисты, очередь, обработка ошибок воспроизведения, скробблинг, настройки, жизненный цикл Electron. Это аудит кода и автоматических сценариев; не подтверждение работы всех внешних сервисов.

## Исправлено

1. При добавлении/удалении локальной папки повторное сканирование заменяло всю медиатеку. Теперь импортированные записи сохраняются, включая поступившие во время сканирования.
2. При отклонённом saveData накопленный патч забывался. Теперь он сохраняется для следующей попытки, новые изменения имеют приоритет.
3. Кэш main обновлялся до успешной записи на диск. Теперь обновляется после атомарного переименования файла.
4. Тексты песен сохранялись отдельным таймером. Переведены на общий механизм накопления изменений и повторного сохранения.
5. Ответ Last.fm с ok:false терял отправленный пакет. Теперь пакет возвращается в очередь так же, как при исключении сети.
6. Единый каталог запускал очередь из одной песни. Теперь очередь содержит доступные записи показанной коллекции и стартует с выбранной.
7. Ошибка аудио обходила альтернативные источники. Теперь они проверяются до перехода к следующей песне. При исчерпании сломанных треков повтор не зацикливает очередь.
8. Миграция v3 повторно интерпретировала готовую тему как старый формат. Настроенная тема теперь сохраняется.
9. Импорт SoundCloud в настройках создавал другой префикс ID, чем поиск, и терял обложку/альбом. Новые импорты используют одинаковые ID и метаданные. Существующие sc: ID не переименовывались, чтобы сохранить ссылки плейлистов.
10. Добавлена блокировка второго экземпляра Electron: повторный запуск показывает существующее окно вместо конкурирующей записи в один профиль.

## Незавершённые функции и остаточные риски

- Last.fm: новый механизм нескольких аккаунтов и старый скробблер используют разные подключения. Новый аккаунт может импортировать коллекцию, но не получать скробблы. Нужен явный выбор аккаунта для скробблинга и единая модель подключения.
- Скробблер дедуплицирует песню на всю сессию приложения, использует позицию воспроизведения вместо реально прослушанного времени и хранит очередь только в памяти. Это не полноценный учёт повторных прослушиваний; требует переработки жизненного цикла прослушивания.
- Быстрое закрытие приложения до 500-мс сохранения не защищено протоколом подтверждения записи между renderer и main. Нужен отдельный сценарий закрытия с ожиданием flush.
- При повреждённом JSON загрузчик молча переходит на defaults. Нужно восстановление из резервной копии и видимое сообщение, чтобы следующий save не затирал единственный повреждённый файл.
- Ошибка сканирования папки может оставить loading=true; необходимо единое отображение ошибки и finally, а параллельные изменения папок требуют сериализации.
- Яндекс: подключение намеренно недоступно из-за отвергнутого Client ID. Это не исправляется вводом телефона или косметикой окна.
- VK: отдельные лайки и сохранённые альбомы не импортируются. Альбомы на главной — группировка треков с метаданными, а не перечень сохранённых альбомов аккаунта.
- SoundCloud: публичный поиск не равен полноценному подключению аккаунта. Доступность потоков и HLS не подтверждена живым воспроизведением.
- Spotify: метаданные не дают права/возможности воспроизводить поток Spotify. Воспроизведение зависит от совпадений с другими источниками.
- Поиск пересобирает источники без подписей аккаунтов; сервисные списки используют менее строгий поиск совпадений, чем единый каталог. Нужна общая модель сопоставления.
- Сохранённые альбомы сервисов всё ещё отображаются иначе, чем карточки основной медиатеки. Общая кнопка альбома может воспроизводить дубликаты источников, хотя строки уже объединены.
- Аудиодвижок подавляет отклонения play(); UI может показывать воспроизведение при отказе запуска. Асинхронное разрешение SoundCloud требует проверки паузы и номера запроса, а не только ID трека.

## Проверка

Регрессионные тесты добавлены для сохранения импортов при смене папок, повторной записи после ошибки, ошибки ответа Last.fm, миграции темы, очереди каталога, альтернативного источника при audio error и остановки сломанных треков при repeat. Существующие тесты авторизации VK проверяют, что исходный /audio без сессии не закрывает окно.

Проверки на реальных аккаунтах и реальное воспроизведение всех сервисов в этот аудит не входят в подтверждённые результаты. Не выполнялись отключение аккаунтов, удаление пользовательских песен или смена секретов.
