# Бэкенд: повторная проверка — 8 октября 2026

Область этого прохода: актуальный main-процесс версии 0.4.0-beta.9, жизненный цикл аккаунтов и импорта, сохранение/восстановление профиля, запись офлайн-файлов. Пересмотрены существующие тесты main, прошлый продуктовый аудит и точки интеграции с IPC. Фронтенд и контракты preload/shared не менялись; другой агент работает с интерфейсом.

## Исправления

- Вход, завершившийся после отключения аккаунта, больше не возвращает удалённый аккаунт в профиль.
- Каждое переподключение инвалидирует предыдущие импорты и обновления токенов. Ответ старого Spotify/Yandex refresh не перезаписывает свежие учётные данные.
- Параллельные импорты одной сессии объединяются. Новый импорт после переподключения ждёт завершения старого браузерного запроса перед повторным использованием partition, но его результат не сохраняет.
- Повторный вход в уже открытое окно авторизации для того же аккаунта отклоняется. Закрытие отклонённой операции не снимает блокировку первой.
- Переименование и изменение autoRefresh во время входа сохраняются, а не заменяются старым снимком аккаунта.
- При отсутствии player-data.json восстанавливается сохранившийся .bak. Повреждённая одиночная резервная копия не заменяется пустым профилем.
- Офлайн-запись переведена на pipeline с обработчиками ошибок до открытия файла. Ошибки открытия/записи и отмена закрывают потоки и переводят загрузку в ошибку/отмену; доступен повтор.

## Проверка

Добавлено 10 регрессионных сценариев: 7 для конкурирующих операций аккаунтов, 2 для отсутствующего основного профиля, 1 для ошибки открытия офлайн-файла и повторной загрузки.

Основной прогон src/main: 189 успешных тестов; один тест junction остановлен ограничением sandbox. Отдельный прогон profileReset.test.ts с необходимыми правами: все 4 успешны. Итого все 190 тестов main подтверждены. TypeScript --noEmit и production build прошли.

Тесты используют поддельные ответы сервисов и отдельные временные каталоги. Пользовательские cookies, токены, музыка и профиль не изменялись. Реальный вход в сервисы, получение удалённой коллекции и установку обновления этот прогон не подтверждает. Сборка включает текущее состояние совместного checkout, но изменения renderer другого агента не проверялись в рамках backend-аудита.

## Оставшиеся вопросы

- OfflineDownloads.resolve проверяет размер файла, но не сохранённую SHA-256: повреждение без изменения размера остаётся незамеченным. Нужна неблокирующая проверка хеша с кэшем результатов.
- Очередь офлайн-загрузок последовательная; зависший источник без собственного тайм-аута может задержать следующие задания. Нужен тайм-аут бездействия с корректной отменой чтения.
- parseProfile проверяет контейнеры musicFolders/playlists/importedTracks, но не все вложенные записи: корректный JSON с неверными типами внутри остаётся отдельным сценарием восстановления.
- Устаревшие сетевые запросы аккаунтов инвалидируются по результату, но не все физически отменяются; некоторое время после отключения они могут продолжать чтение сервиса. Они больше не имеют права записывать результат.
- Внешние возможности VK/Яндекс и актуальные ограничения API не проверялись в сети; текущие сообщения о неподдерживаемых разделах сохранены.
